# Treino do adaptador LoRA e teste contra o modelo sem treino (T038) — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Preparar os dados do `br-doc-extraction` no contrato da saída do VLM, treinar um adaptador LoRA do Qwen3.5-4B em GPU de 24 GB na nuvem, carregá-lo no Ollama local e comparar adaptador × modelo sem treino nas 81 imagens de teste.

**Architecture:** O que é determinístico e testável (alinhamento arquivo↔linha, conversão de rótulos, geração do JSONL, métricas) fica em `src/backend/visiondoc/treino/` com testes unitários. O que depende de GPU, de rede ou do Ollama (treino, conversão GGUF, avaliação) fica em scripts descartáveis `infrastructure/treino-t038/` e em um notebook, com verificação por comando. A prova pequena (Tarefa 4) precede o treino completo e bloqueia as tarefas seguintes se o adaptador não carregar no Ollama.

**Tech Stack:** Python 3.12, `uv`, `pytest`, `ruff`, `pydantic`, `httpx`; treino (nuvem): biblioteca a escolher na Tarefa 4 (Unsloth ou TRL+PEFT+bitsandbytes), `mlflow`; conversão: `llama.cpp` (`convert_lora_to_gguf.py`); Ollama 0.40.17 com `qwen3.5:4b`.

**Spec:** `docs/superpowers/specs/2026-11-26-treino-lora-t038-design.md`. Decisões: `docs/decisions/ADR-015-vlm-qwen35-4b.md`, `ADR-017-ollama-servidor-do-vlm.md`; contrato em `docs/contracts/saida-vlm.md`.

## Global Constraints

- Python `>=3.12,<3.13`; dependências via `uv`; código em `src/backend/visiondoc/`, testes em `tests/backend/`; `ruff` com `line-length = 100`.
- Dados: só `tech4humans/br-doc-extraction` (público, sintético); nada além do dataset vai para a nuvem (ADR-009, ADR-015). `data/raw/` e `data/processed/` ficam fora do git.
- Partição do dataset, sem reparticionar: treino `0–1061`, validação `1062–1136`, teste `1137–1217` (numeração global dos arquivos `<split>-<NNNNN>.png`); 1062 / 75 / 81 linhas. O teste não entra em nenhuma decisão de treino.
- Alvo no contrato `SaidaVLM`: um documento por imagem; `bbox = [0, 0, 1000, 1000]`; `face = null` (emitida); `invoice` → `tipo: "outros"` com `campos: {}`; valor `""` → `null`; campo ausente no rótulo → chave **omitida** (não `null`).
- Instrução de sistema fixa, a mesma de `infrastructure/poc-t020/poc_vllm.py` (`INSTRUCAO`); turno do usuário: imagem + o texto fixo `TEXTO_USUARIO`; sem transcrição.
- LoRA: QLoRA 4 bits, codificador de visão congelado, modelo de linguagem com rank 16, alpha 32, dropout 0,05.
- Inferência no teste: Ollama `/api/chat`, `think: false`, `temperature: 0`, esquema em `format` (ADR-017).
- Mensagens de commit terminam com `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Linha do dataset com `response` que não é JSON, ou `type` desconhecido:** é descartada e contada no relatório; nunca levanta exceção (Tarefa 2).
2. **Chaves sinônimas na mesma linha** (`nome` e `nome_completo` juntas; uma vazia): vale a de maior prioridade com valor não vazio; vazio não sobrescreve preenchido (Tarefa 2).
3. **Pasta de imagens incompleta, com arquivo de índice fora de 0–1217 ou prefixo que não bate com a faixa** (ex.: `test-00005.png`): falha explícita antes de gerar qualquer JSONL (Tarefa 3).
4. **Filiação só com pai, só com mãe ou ambos vazios:** lista só com os presentes; ambos vazios omitem a chave, nunca `[""]` (Tarefa 2).
5. **Vazamento do teste no treino:** nenhum `id` de teste ou de validação aparece em `train.jsonl` (Tarefa 3).
